⊞ BLOCK 6 — VENDOR PACKAGE & SDK EVIDENCE

- C316H User Manual.pdf
- UHF-A4_v1.8.1.apk_Decompiler.com.zip
- app/libs/DeviceAPI_ver20251103_release.aar

Confirmed from vendor code/documentation:
- URA4 with SM6115 maps the extended/external UART to /dev/ttyHS2.
- SDK class Module exposes init(int module, int baud, int databits, int stopbits, int check).
- SDK class Module exposes receiveEx() and closeSerail().
- Module number 10 is documented as the A8 external/extended UART.
- Module.init(10, 9600, 8, 1, 0) is the documented initialization path for that UART.

Evidence boundary:
- The vendor materials inspected do not establish the reader-side DB9 pin-number mapping.
- No cable/adapter wiring arrangement is accepted as correct until electrically verified or proven by received bytes.

WORK ORDER: TRS-TX-002-RWA
Title: Associate stable livestock weights with RFID records
Revision: 1
State: PROPOSED
Proposed: 2026-09-30
Authority required: Michael ratification and assignment
Target base: codex/trs-tx-001-eui after TRS-TX-001-EUI verification

Objective:
- Combine the proven scale stream and RFID inventory stream into one auditable livestock weigh record without weakening the working reader or raw diagnostic path.

Proposed operating flow:
1. Operator starts or resumes a Sentinel session and enters Weigh Mode.
2. The configured chute antenna observes the animal EPC.
3. The scale parser receives SellEton ASCII frames and recognizes stable/gross/net/sign/value/unit fields.
4. A candidate weight is locked only after three stable frames agree within one scale division.
5. The app associates the candidate with one recently observed chute EPC.
6. The app presents EPC, matched HerdMate animal, weight, unit, antenna, and timestamp for operator acceptance.
7. Accepted records are stored with the session and survive app closure.

Association safety rules:
- Exactly one eligible chute EPC in the association window permits automatic staging.
- Zero EPCs produces an UNMATCHED WEIGHT candidate; no silent assignment.
- Multiple EPCs produce an AMBIGUOUS candidate; the operator must choose or reject.
- Never choose an animal solely by strongest RSSI when multiple eligible tags are present.
- A new stable weight must not overwrite an earlier accepted record.
- Raw scale frame and RFID evidence remain attached for audit and troubleshooting.

Proposed data record:
- weightEventId UUID
- sessionId
- epc
- matched animal identifier when available
- weight value normalized to pounds
- original numeric value and unit
- stable flag
- gross/net status
- sign
- raw scale frame
- scale timestamp
- accepted timestamp
- antenna identifier
- RFID first/last seen timestamps within the association window
- RFID read count and strongest RSSI within that window
- association state: MATCHED, UNMATCHED, AMBIGUOUS, REJECTED
- operator acceptance state and operator identity

Proposed implementation scope:
- Extract the working module-10 serial logic into a reusable scale component while preserving Scale Debug.
- Add a tested SellEton frame parser for the observed ST,GS,+ 125lb format and documented variants.
- Add a Weigh Mode panel to the main Sentinel screen.
- Add per-session WeightEvent persistence and restore support.
- Advance session JSON schema from 0.7 to 0.8 with backward-compatible loading.
- Include accepted weight events in JSON and CSV exports.
- Display accepted weights in session history and tag/animal detail.
- Preserve existing RFID, animal lookup, GPS, weather, and antenna-power behavior.

Acceptance evidence:
1. Existing RFID inventory and Scale Debug regression tests pass.
2. Stable 125 lb input parses as stable, gross, positive, 125 pounds.
3. One eligible EPC plus a stable weight stages the correct combined record.
4. Zero and multiple EPC cases cannot silently create a matched record.
5. Operator can accept or reject a staged record.
6. Accepted record survives force-stop/reopen and session restore.
7. JSON and CSV exports contain EPC, animal identity when available, weight, timestamp, antenna, and raw evidence.
8. Android build and automated tests pass before field installation.

Explicit exclusions:
- No HerdMate write-back or cloud synchronization.
- No automatic assignment when multiple cattle tags are in range.
- No removal of the Scale Debug evidence screen.
- No claim of legal-for-trade weighing certification.
