Livestock behavior:

Serial format:
- 9600 baud, 8 data bits, no parity, 1 stop bit.

- Indicator DB9 documentation: pin 2 TX, pin 3 RX, pin 5 GND.

⊞ BLOCK 6 — VENDOR PACKAGE & SDK EVIDENCE

Vendor artifacts obtained:
- API_Ver20251103.rar
- doc.rar
- C316H User Manual.pdf
- UHF-A4_v1.8.1.apk_Decompiler.com.zip
- app/libs/DeviceAPI_ver20251103_release.aar

Confirmed from vendor code/documentation:
- URA4 with SM6115 maps the extended/external UART to /dev/ttyHS2.
- SDK class Module exposes init(int module, int baud, int databits, int stopbits, int check).
- SDK class Module exposes receiveEx() and closeSerail().
- Module number 10 is documented as the A8 external/extended UART.
- Module.init(10, 9600, 8, 1, 0) is the documented initialization path for that UART.

Evidence boundary:
- The vendor materials inspected do not establish the reader-side DB9 pin-number mapping.
- No cable/adapter wiring arrangement is accepted as correct until electrically verified or proven by received bytes.

⊞ BLOCK 7 — CURRENT APP & FIELD TEST EVIDENCE

Current Scale Debug behavior:
- UART path: /dev/ttyHS2.
- Serial parameters: 9600 8-N-1.
- The screen reports OPEN SUCCESS.
- It then reports Waiting for indicator bytes.
- Field counters remain Bytes: 0, Chunks: 0, Complete lines: 0.
- Repeating the test with the available mini adapters produced the same zero-byte result.

Implementation observed on scale-debug-v1-mobile:
- ScaleDebugActivity uses Module.getInstance().openSerail(activePath, activeBaud, 8, 1, 0).
- Receive loop uses receiveEx().

Current diagnosis:
- PROBABLE, NOT FIELD PROVEN: openSerail() opens the device node but may not perform the power/mux/module initialization performed by init(10, ...).
- A successful open message proves the file opened; it does not prove electrical receive data is reaching the application.
- Cable polarity/pinout remains an independent possible blocker.
